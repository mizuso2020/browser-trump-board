# 仕様: オンライン対戦 / 掲示板・スタンプ / 募集中の部屋

作成 2026-08-18。実装前の合意用。フェーズごとに区切って進める。

---

## 調査で分かったこと

### オンライン対戦はほぼ完成している

「離れた場所で遊ぶ」は未実装だと思われていたが、**実際には room モード（各自のスマホ）と
同じコードで動く**。各ゲームの分岐は例外なく次の形になっている。

```js
return room.mode === "room" || room.mode === "online";
```

同期も `Sync.isOnline()` が両モードを同じ扱いにしており、HTTPポーリングは
インターネット越しでもそのまま動く。参加リンクも既に公開ドメインを指している。

塞いでいるのは **[sync.js:43](../js/sync.js) の1行だけ**。

```js
canUseMultiDevice: function (mode) {
  if (m === "room") return true;
  if (m === "online") return isFirebaseConfigured();  // ← ここ
  return false;
}
```

`firebase-config.js` は空のままなので常に false になり、[room.js:226](../js/room.js) の
ガードで弾かれる。オンラインを Firebase で作る初期構想の名残で、その後に
HTTPルームAPIへ移行したときに取り残されたと思われる。

同じファイルの `shouldUseServerApi()` は `online` でも HTTP API を使う判定に
なっており、**2つの関数で前提が食い違っている**のが根拠。

### 足りないもの

| 項目 | 現状 |
|------|------|
| チャット・スタンプ | 実装なし。離れた場所での人狼は議論できず成立しない |
| 部屋の一覧 | APIにエンドポイントなし |
| 部屋の寿命管理 | **掃除処理が一切なく、作られた部屋がディスクに残り続ける** |
| 参加者の追い出し | ホストがキックする手段がない |

## フェーズ1: オンラインモードを開く

一番小さく、一番効果が大きい。

- `canUseMultiDevice()` の Firebase 依存を外し、HTTPルームAPIで判定する
- `modesSoon` から `"online"` を外す（23タイトル）
- **[room.js:1040](../js/room.js) 他の `room.mode !== "room"` 制限を見直す。**
  大富豪・テキサスホールデム・99・爆弾・ブラックジャック・ナンバーリンク・将棋の
  7タイトルがオンラインで弾かれる書き方になっている
- 使われていない Firebase 経路（`firebase-config.js`、`js/vendor/` の SDK）を整理

検証: 別オリジン3つで実際に対戦できることを確認する（今回の手法が使える）。

### 判断が要る点

離れた場所では「端末を渡してください」が成立しない。1台モード用の文言が
オンラインで出ないか、ゲームごとに確認が必要。

## フェーズ2: 掲示板（チャット）とスタンプ

フェーズ1を実用にするための本体。**人狼・ワードウルフ・コードネームは
議論できないと遊べない。**

### サーバー

```
GET  /room/{code}/messages?since={id}   参加者のみ。差分取得
POST /room/{code}/messages              参加者のみ。1件追加
```

- 既存のトークン認証（`X-Room-Token`）をそのまま流用する。参加者以外は 403
- 追記のみ。1部屋あたり上限（例: 200件）を超えたら古いものから捨てる
- 1件の長さ上限、連投の間隔制限をサーバー側で持つ
- スタンプは「種類IDだけを送る」形にする。任意画像のアップロードはしない

### クライアント

- ルーム画面に折りたたみ式のチャット欄
- スタンプはプリセット絵文字のパレット（20種程度）
- 既存のポーリングに相乗りする（別ポーリングを増やさない）

### 判断が要る点

- **人狼の死者・霊界チャットをどうするか。** 全員が同じ掲示板だと、
  追放された人が生存者の議論に割り込める。ゲーム側の状態と連動させるか、
  単純な1本の掲示板にとどめるか
- 夜フェーズで人狼だけの相談を許すか（役職ごとのチャンネルが要る）

## フェーズ3: 募集中の部屋一覧

見知らぬ人と遊べるようにする。**フェーズ2が前提**（会話手段が無いと成立しない）。

### サーバー

```
GET /rooms/open   公開設定かつ lobby 状態の部屋一覧
```

返すのは部屋コード・ゲーム名・現在人数/上限・作成時刻まで。
**秘密情報や参加者の名前は返さない。**

### クライアント

- 新規ページ `rooms.html`（トップから導線）
- 部屋作成時に「公開して募集する / コードを知っている人だけ」を選ばせる。
  **既定は非公開**

### 先に片付けるべき前提

1. **部屋の寿命管理。** 現在まったく掃除していないため、一覧を作ると
   死んだ部屋が並ぶ。最終更新から一定時間で消す仕組みを先に入れる
2. **ホストによるキック。** 公開する以上、迷惑な参加者を外せないと運用できない
3. **通報の受け口。** 最低限、部屋コードを添えて連絡できる導線

### 判断が要る点

- 見知らぬ人同士のチャットになるため、名前や本文の扱いを決める必要がある。
  年齢層が低い可能性も踏まえて、どこまでやるか
- 4桁コードは総当たりで到達しうる。秘密情報はトークンで守られているが、
  **部屋への飛び入り自体は防げない**。桁数を増やすか、公開部屋のみ許すか

---

## 進め方の提案

フェーズ1 → 2 → 3 の順。1は小さく即効性があり、2が無いと1が実用にならず、
3は2が前提になるため。

各フェーズごとに動作確認して区切る。
